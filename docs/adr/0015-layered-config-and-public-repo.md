# 0015. Layered config; a public repo with nothing personal in it

- **Status:** Accepted
- **Date:** 2026-10-25 (public since 2026-10-26)
- **Related:** 0004, `rules.local.default.toml`, `tests/test_readme.py`

## Context

v2 needed personal settings (the model path, optional keyword rules) that
must survive reinstalls and must not be published. Then the owner decided to
publish on GitHub ("can we upload this to github?"), and later to make it
public: "i am having a few friends test it out". The owner's Gmail address
was in early commits.

## Decision

- **Config layers:** `rules.default.toml` (tracked, generic) →
  `rules.toml` (generated by `setup.py`, git-ignored) and
  `rules.local.toml` (personal, git-ignored, created once from
  `rules.local.default.toml` and never overwritten). Local rules are
  evaluated before the shipped ones. `setup.py --model PATH` writes the model
  path safely, so nobody hand-edits TOML quoting.
- **Nothing personal is published:** no home paths, no model or app names,
  no course codes in tracked docs, defaults or tests. A test fails the build
  if a home-folder path or the original model's name appears in the README, the
  reference docs or the default rules.
- **Identity:** history was rewritten so commits use the GitHub
  `noreply` address; the repo-local `user.email` is set to it.
- **Transport:** `origin` uses SSH ("lets use ssh this time around") with a
  dedicated key whose passphrase is kept in the macOS Keychain.
- **Releases:** tagged `v1.0.0`, `v2.0.0`, `v2.1.0`; pushing and publishing
  happen only after the owner says so.

## Consequences

- Friends clone a tool with no trace of the owner's machine.
- Updating is `git pull` plus `./install.sh`; personal settings stay put.
- The pre-rewrite history survives only in a local backup bundle.

## Alternatives considered

- **One config file:** reinstalling would wipe personal settings.
- **A private repo:** friends could not test it easily.
- **HTTPS with a token:** the owner's usual method; SSH was chosen this time.
